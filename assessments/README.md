# Assessments and Examination Standards

Assessment is designed to test independent reasoning, not recognition or note production. Map each assessment to the [program competency framework](../curriculum/competency-framework.md); an outcome should not be claimed as mastered unless an assessment produces observable evidence.

## Course-level assessment package
Each course should contain:
- diagnostic prerequisite check;
- problem sets with worked solutions or solution outlines;
- one computational lab with tests;
- a short literature/source synthesis;
- a final project prompt and rubric;
- an oral-defense-style question set for self-review.

## Problem-set design
Problems should progress from derivation to application and critique. Require units, assumptions, intermediate steps, and interpretation. Numerical answers without reasoning receive limited credit.

## Oral defense / self-examination
For each final project, answer without notes:
1. What is the central question and why does it matter?
2. What assumptions drive the result?
3. Which alternative model or interpretation could change the conclusion?
4. What evidence would falsify the claim?
5. What is the largest limitation?
6. What would be required to apply the result to a real utility or policy decision?

## Assessment record
Record date, score, feedback, revisions, and links to evidence in the progress tracker. A score is an internal diagnostic, not a credential.
