# Academic Progress Tracking

This folder records the learner's actual work and supporting evidence. It is a personal academic record, not an automatically completed checklist.

## Files

| File | Purpose | Update when |
|---|---|---|
| `academic-transcript.md` | Courses completed and evidence-based internal assessments | A course completion gate is met |
| `course-tracker.csv` | Course-level status, planned/actual hours, and evidence | Starting, pausing, or completing a course |
| `year-1-assessment-tracker.csv` | Individual Year 1 problem sets, labs, source exercises, and deliverables | Each assessment is attempted or reviewed |
| `year-1-study-plan.md` | Recommended sequence, time budget, and completion gates | Scope or schedule changes |
| `reading-tracker.csv` | Source-level reading progress | A source is read or revisited |
| `research-log.md` | Questions, decisions, results, and next actions | At the end of a meaningful study/research session |
| `annual-review-template.md` | Annual audit of progress, gaps, and priorities | At an annual review |

## Status definitions

Use exactly one of these values in tracker status fields:

- **Not started:** no substantive attempt has been made.
- **In progress:** work has begun but the completion evidence is not yet adequate.
- **Blocked:** progress depends on a missing prerequisite, source, dataset, or decision.
- **Completed:** the defined work and review are finished, with an evidence link.
- **Deferred:** intentionally postponed; record the reason in notes.

Do not mark work completed because a page exists, a solution has been generated, a test passed, or material has been read.

## How to update the trackers

1. Record actual hours, not intended hours.
2. Link the submitted derivation, code, report, notebook, or source log in `evidence_url`.
3. Use `score_out_of_24` only for a reviewed deliverable assessed against the internal rubric in [Academic Standards](../ACADEMIC_STANDARDS.md).
4. Explain significant errors, revisions, or remaining limitations in `review_notes`.
5. Keep a course in progress until its course-level completion evidence exists.
6. Preserve prior evidence when a course is revised; do not overwrite history to make progress appear cleaner.

The planned hours are estimates for scheduling. They should be recalibrated from actual time and are not deadlines or grades.

## Evidence standard

A strong completion record links to work that can be inspected and, where relevant, reproduced. For a computational project, include the inputs or source references, environment/dependencies, run instructions, tests, and limitations. For a policy analysis, include primary sources, version/effective dates, a clear institutional scope, and a distinction between fact, interpretation, and recommendation.

The program is designed around 3–5 hours per week. Extend the calendar when needed; do not lower the academic standard to preserve a target date.
